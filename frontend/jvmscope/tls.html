Getting started

  • Use Choose TLS log or drop a JSSE debug log onto the page. The table and inspector appear after a capture is accepted.
  • Full sample opens the built-in overview. Browse examples, or the arrow beside Full sample, opens named Java 25/26/27 captures and focused TLS cases. Cards label controlled JVM captures and synthetic scenarios. Selecting an example replaces the capture; browsing keeps your current data.
  • A new file resets time, host, SNI and failure-category selections. Generic search, outcome and direction filters remain active. Clear filters keeps the capture; Clear removes it and resets every filter. Reloading clears the in-memory capture.

Search, filters and timeline

  • Search for host, SNI, cipher, TLS version, outcome, reason or warning text. Use Failures, Success, Warnings and direction controls to narrow the list.
  • In Capture analysis, drag across the timeline or enter UTC times to select a period. Interactions overlapping it are included. Zoom changes the scale only; it does not apply a period filter.
  • Select multiple hosts or SNI names and a failure category. Values within one filter are combined; different filters must all match. Choice counts apply the other active filters. Remove filter chips or use Clear filters to recover the full capture.
  • Without time shows missing, ambiguous or backwards-moving timestamps. These interactions have no reliable observed span and are excluded from period filters.
  • Timeline bars count interaction starts, colored by the full interaction outcome. A red bar does not locate when failure occurred. Observed span includes closure and is not handshake latency.

Inspecting interactions and evidence

  • Select a row in Investigate to follow its observed sequence. Source-line links jump to the original evidence. The inspector stays open as you move between interactions.
  • Overview and All columns offer wider tables. Full details opens the complete summary; diagnostic explanation buttons describe a matched issue, possible causes and checks.
  • The sequence follows file order. Produced and consumed messages are JSSE observations, not verified network delivery. An outbound SNI is a requested server name, not a captured network address.
  • Missing messages mean not captured, not that they never happened. Transport errors alone cannot establish who reset a socket or place the error before ServerHello.

Expected input and interpretation

  • Supports SunJSSE console format families used in Java 7–27: legacy *** ClientHello, compact javax.net.ssl|DEBUG|... and expanded output. Controlled captures exercise available TLS 1.2/1.3 protocols, client authentication and trust failures; additional Java 25–27 fixtures cover expanded output. Check the generated compatibility matrix for exact builds and providers. This does not certify every vendor, update or platform; custom logger wrappers and other TLS providers need separate verification.
  • Expanded JSSE output is not necessarily valid JSON. Use the original debug log rather than treating an expanded message as a JSON input document.
  • Legacy bodies omit reliable thread IDs and timestamps. Interleaved captures, or a new ClientHello before the previous handshake has a captured completion or fatal failure, leave subsequent legacy groups unknown. Capture each connection separately. Missing protocol, cipher, certificate and time values are not guessed.
  • Java 27 hybrid key-exchange records, including X25519MLKEM768, remain in the raw log and observed sequence. They still describe TLS 1.3; the analyzer does not separately classify the negotiated key-exchange group.

Collecting a TLS log

  • Run java -Djavax.net.debug=ssl,handshake -jar app.jar > tls.log 2>&1. Put the JVM option before -jar or the main class. Replace app.jar with your application.
  • -Djavax.net.debug=ssl,handshake,expand also enables supported expanded output. Keep stdout and stderr in their original order; avoid concatenating logs from different JVMs.
  • Capture the complete handshake and any subsequent fatal alert. Partial output limits the conclusions you can draw. SunJSSE’s debug options depend on the TLS provider in use.

Outcomes, warnings and grouping

  • Success means a local Finished exchange or explicit completion was observed. It does not certify peer acceptance or application health. A later fatal alert is still a failure.
  • Warnings are matched diagnostic keywords, including certificate-selection messages. They can occur in successful handshakes and do not independently prove failure. Unknown means the capture does not support a safe outcome.
  • Modern interactions use JVM thread IDs and handshake boundaries; a pause does not start a new connection. Thread IDs are not connection IDs. Asynchronous engines, shared workers and combined process logs may require separate captures.
  • A new ClientHello before the previous handshake has completed or failed, or conflicting ServerHello/Finished observations, produce an unknown outcome and a grouping warning. Unresolved boundaries keep subsequent groups on that JVM thread uncertain; other threads remain independent. HelloRetryRequest stays in its original group. Original records remain accessible, while negotiated/certificate summaries are withheld. Other interleaving may be undetectable; consult the source evidence.

Full sample coverage

  • The comprehensive synthetic sample demonstrates TLS 1.2/1.3, inbound/outbound success, resumption, ALPN, clean closure and interleaved handshakes.
  • It includes successful and failed mutual TLS, requested certificate authorities and selected client certificates.
  • Failure cases include trust, hostname, protocol, SNI, ALPN, cipher/algorithm, timeout, reset, EOF, broken pipe, certificate and incomplete-capture symptoms. Use the named example library for smaller focused cases and controlled JVM captures.

Privacy and performance

  • Logs are read and analyzed locally in a disposable browser worker. Captures are not uploaded and the tool sends no telemetry. Built-in examples are downloaded from this application’s server, then analyzed locally.
  • Clear or a newer input cancels pending analysis. The table shows 200 interactions per page; filters, timeline and inspector navigation cover the full capture. Available browser memory limits large files.
  • Reload or Clear removes the in-memory capture. Copy actions place the selected original evidence on your clipboard.
